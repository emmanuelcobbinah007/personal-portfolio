---
title: "Don’t master a language, master the materials"
excerpt: "A friend asked how to master a programming language. My answer: don’t. Learn the materials instead."
date: "2026-09-30"
---

“Emmanuel, how do I master a programming language?” a friend asked me. She felt she was being left behind.

This was my answer: at this point, focusing on mastering a single programming language is not the best use of your time.

Writing code is just one piece of the engineering puzzle. It used to be our primary concern because it took the most time and was the most visible output. Today, producing code is cheap. Producing correct code, code that handles edge cases, fits the system, and doesn’t break in production, is still hard.

Think of it like learning French. Instead of memorising one language’s vocabulary, learn how languages work, then bring in a translator when you need one.

The same applies to code. Reading and understanding code quickly is now more valuable than writing it from scratch.

So don’t chase mastery of one language. Focus on the building blocks that every language shares: variables, data types, conditionals, loops, and functions. Then let an LLM help with the syntax layer for whatever you’re building.

But don’t skip the practice. Pick one language as a vehicle, build small projects, and get comfortable debugging and testing. That hands-on time is what builds the judgment to tell when an AI’s answer is wrong.

Then zoom out. You don’t need everything at once, but over time, build familiarity with data structures and algorithms, networking basics, software architecture, system design, and how software gets deployed and maintained.

Software engineering is more than writing code, just as civil engineering is more than building a bridge.

You need to understand the materials well enough to judge the work.

Coding used to be the flashy part. Times have changed, and so must we.
